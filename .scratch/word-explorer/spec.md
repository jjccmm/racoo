## Confirmed user behavior

- Exactly one visible search input on the main page, with a labeled accessible autocomplete dropdown, at most ten matching published lemmas. Use existing non-stopword vocabulary and its substring matching with NFC/case normalization. Prefer an exact match, then prefixes, then other substring matches; use totalCount descending and lemma for ties. Dropdown is opened only while interacting, supports mouse/touch, ArrowUp/Down, Enter, Escape and dismissal on outside click. It is not a row of suggestion buttons below the input.
- Selected words appear immediately beneath the input as colored removable word chips. Clicking a chip removes that word, with a clear accessible removal label; don't add a separate remove-only button beside each word. Reset input after a selection, prevent duplicates, retain existing maximum of five simultaneous words. Each selected word keeps its color until removed; chip, chart series, per-episode counts and highlighted text use the same color.
- The stacked vertical bar chart is the main page element. X axis is episodes with visible useful labels; Y axis is absolute occurrences. One stack per selected lemma, showing per-word and summed counts in its tooltip/legend. No rate-per-1000 option, normalization controls or normalized values in the active explorer.
- A clear two-state control selects Top 10 (default) or Alle. Top 10 includes at most ten episodes with positive total counts and sorts by sum across selected words descending; tie-break publication date descending then stable ID. Alle plots every episode chronologically by publication date then stable ID, including zeros. Keep readable bars/episode labels via contained horizontal scrolling for larger datasets and at narrow widths; never widen the whole page.
- Below the chart, show at most ten positive-count episode cards in the same summed-count order as Top 10, independently of the Alle chart toggle. Each shows title/date, total count, and each selected word's exact count including zero. These counts come from the compact schema2 statistics, not Pagefind result positions. A small expandable chart-data table can supply accessible exact values for the currently plotted episodes without competing with the chart.
- Load original text/fundstellen only for the ranked top ten episodes (no archive-wide transcript loading). Reuse the existing Pagefind index and wordform-aware matching, restricting detail loads to requested episode identities before fragment loads; do not let native Pagefind rank reorder the statistics-ranked cards or omit a high-count card merely because it is outside Pagefind's first native ten.
- Cards show matching coarse segments with selected terms highlighted in their corresponding colors, preserving original wording and treating source text as text (no unsafe HTML injection). Highlights should follow actual matching surface forms/positions where possible (Münze may highlight Münzen), not arbitrary substring replacement. Keep the distinction between exact spaCy lemma counts and lexical Pagefind wordform/prefix matches explicit in a concise user note. If the lexical index cannot locate a counted lemma, keep the exact count/card and show a truthful no-matching-text state rather than claiming zero occurrences. No new ASR, spaCy reanalysis, fine wordtimestamps or full-corpus token annotations for this UI change.
- Long text segments show a bounded excerpt around hits, with full original segment text available on demand; don't hide every matching passage permanently. Preserve coarse segment playback, adjacent advertising warning, one shared player, original episode link, direct ?episode=&t= links, manual retry after errors and no autoplay for shared links.
- Selection changes must abort/ignore obsolete text requests; old results cannot overwrite new ones. Count-loading and passage-loading errors are distinct from zero/no-hit, visible and manually retryable. Remove selected words safely during loading, clear results on empty selection and don't leave removed colors/series behind.
- Automatically open the main word explorer at page load (no Wortstatistik öffnen gate). Startup may load publication, compact statistics catalog/vocabulary and UI code; no count shard/transcript/fragment before actual selection. Preserve stopword/manual-list exclusion notice near the input, overall word metrics and measured episode timing overview, with secondary metadata below the main experience in disclosure sections. Publication/pilot and ASR/advertising notes remain concise and visible; no duplicate search input in secondary sections.
- Preserve static hosting, existing 64 hash shards, single vocabulary file, stable IDs and publication binding at both / and /podcast_words_v3/. No alphabet files, frequency-ranked shards, new general cache, worker persistence refactor, backend, dependency additions or unrelated processing change.

## Visual direction

The chart gets the largest white/soft-green panel, clear hierarchy, generous height and legible labels. Supporting notices are short, lower priority; per-episode cards are scannable. Use one consistent five-color palette across chips, legend, stacks, count badges and text highlights. Typography, borders, keyboard focus and empty/error states should feel finished without adding unrelated illustration or animation.
